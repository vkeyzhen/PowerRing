# PowerRing 项目介绍

> 这份文档是给人看项目用的：它是什么、为什么长成现在这样、边界在哪。
> 功能细节与用法在 [README](../README.md)，加设备的具体操作在
> [adding-a-device.md](adding-a-device.md)。

## 一句话

Windows 托盘里的一圈电量环，把无线鼠标、耳机、手柄的剩余电量放在同一个地方看 ——
不用为每个品牌装一个厂商软件，也不用为了看眼电量去打开它们的客户端。

单文件 exe，约 1 MB，免安装、不需要管理员权限、不自动联网、没有账号。

## 它解决的是个很小的麻烦

无线外设的电量分散在各自的厂商软件里：罗技在 G HUB，HyperX 在 NGENUITY，
雷蛇在 Synapse。它们的共同点是 —— 为了看一眼「还剩多少」，你要先启动一个几百 MB
的程序。而这件事本身只需要一个数字。

Windows 自己在设置里能给一部分蓝牙设备显示电量，但走 USB 接收器的鼠标基本没有。
PowerRing 就是把这个数字单独拎出来，放在最不需要打开任何窗口的地方：托盘。

## 现在能做什么

| | |
| --- | --- |
| **托盘电量环** | 从 12 点起顺时针填充，填多少就是还剩多少。绿 → 橙 → 红对应档位，充电时转蓝 |
| **悬停看数字** | 多台设备时按电量从低到高排，用短名（GPW / Cloud Flight），一两秒扫得完 |
| **左键面板** | 每台设备的完整名字与电量，左侧色块对应档位 |
| **低电量提醒** | 只在跨过阈值的那一刻弹一次，卡片锚在托盘旁边，30 秒/8 秒自动收起 |
| **自动发现** | 没写进声明的设备也会被试着认出来，认出来就落成一份声明，下次直接命中 |
| **声明同步** | 点了才联网，拉一份最新的设备清单，拉到立刻生效，不用升级 exe |
| **设置** | 刷新间隔、两级阈值、提醒开关（带「试一次」）、开机自启、界面配色、自定义同步地址 |

## 三个决定，决定了它长成这样

### 一、读不到就是读不到

电量读不出来时，显示灰环和两个短横，**绝不用 0% 或任何猜出来的数字顶上**。
这条听起来像常识，但实际会遇到几个不好分的情况：

- **鼠标睡着了**。接收器照样答应探测，连名字都读得到，但电量请求连着 20 次
  没人应答。这时候该保留上一次的读数 —— 一动错就把界面打回灰环，
  托盘会每隔几分钟闪一下。
- **鼠标睡得更久，连探测都不答了**。HID 接收器上「深睡」和「关机」在协议层
  长得一模一样，无从分辨。于是选择是：**分不清就不要装作分得清** ——
  标成「未连接」留在托盘，等它自己回来，而不是让它消失、等用户动一下鼠标再冒出来。
- **真的拔了**。判据换成「写入成不成功」：写不进去就是硬件没了，这是硬证据，
  立刻移出列表。

三种情况用了三层判据，代价是这个模块比看起来复杂。但这正是「可信」的含义：
用户看到的每个数字都是真的读到的。

### 二、不自动联网

没有遥测、没有静默的更新检查、没有崩溃上报。整个程序只有**一个**地方会发请求：
托盘菜单里的「检查设备声明更新…」，而且只有用户点了才发，拉不到就安静退让。

连这个唯一的功能也是可关的：拉不到就等于这次没更新，已有的设备照常显示。
在连不上 GitHub 的网络里，程序的其他部分完全不受影响。

### 三、加一台设备 = 加一份 YAML

设备协议住在 `devices/*.yaml` 里，不在代码里。每份声明描述的是**事实**：
VID/PID、走哪个接口、问哪个 feature、报文是什么字节、响应里取第几个字节、
数值怎么换算成百分比。

结果是：接一台从没被支持过的新设备，可以不改一行 Rust 代码。HyperX 天箭
就是这样接进来的 —— 它用私有报文，四行声明写清了「发什么、读哪几个字节、
查哪张分段表」，代码零改动。

凌豹 MK75 是第二个例子，也是更好的例子：它和天箭一样走私有报文，但形态差得
很远 —— 一问会回两帧、充电时只是多置一个标志位而不是把数值换义。这两种差别
原本在声明格式里根本没有表达的地方。解决办法不是给 MK75 写一段专用代码，
而是往声明格式里补两个可选的字段（`reply_prefix` 挑帧、`charging_mask` 按位判充电），
于是任何形态相近的设备都能靠填表接进来。

这也是这个项目目前最有价值的贡献方式：**你不需要会写代码**。

## 能认哪些设备

按「能不能用公开标准读到」分成三类，难度依次上升：

| 类别 | 例子 | 需要什么 |
| --- | --- | --- |
| 蓝牙标准电池服务 | Xbox 手柄、部分键盘与耳机 | 只要 VID/PID。百分比是**设备自己报**的，与 Windows 设置里同源同值 |
| 罗技 HID++ 2.0 | GPW（接收器或插线） | 问它支不支持电量 feature（`0x1001` 电压式 / `0x1004` 百分比式），答应**并且真读到一次合理电量**才算数 |
| 私有报文 | HyperX 天箭、凌豹 MK75、雷蛇系 | 需要有人提供报文格式。写进声明就行，零代码 |

一个接收器上挂着的设备会被**逐个 slot 问遍**，不会只认第一台。
认出来的设备会写成一份标准 YAML 落在用户目录，可以删（删了下次重探），
也可以整份贴进 Issue —— 它本身就是一份能直接合并的声明。

## 边界（明确不做的）

- **不做厂商软件的替代品**。不改 DPI、不设灯效、不做宏。只读电量这一个数
- **不做高频轮询**。默认 60 秒一轮，所以任何变化最多要等一轮才被看到。
  这是刻意的：为了「立刻发现」去高频发探测报文，会把正在休眠的设备叫醒，
  等于替它耗电。拔接收器通常半分钟内从托盘退下，插回来在下一轮扫描里出现
- **不碰系统目录**。配置和日志都在 `%APPDATA%\PowerRing`，卸载就是删掉文件夹
- **AirPods 这类走私有协议的蓝牙耳机不支持**。它们的电量本来也由系统展示
- **不做跨平台**。用的是 Win32 与 hidapi，Windows only

## 体积与技术选择

`~1 MB` 单文件、无运行时依赖。这个数字不是目的，是几处选择的结果：

- 不引 GUI 框架。托盘图标是手绘 RGBA，面板/卡片/设置窗口都是自建 `WS_POPUP`
  窗口 + 自绘控件。理由很实际：这个项目的反馈循环是「改一行 → 编译 → 用户截图」，
  拖进 winit/wry 会让每次增量编译从几秒变成几十秒
- 不引 HTTP 依赖。同步用系统自带的 WinHTTP，不为一处一年点不了几次的功能
  塞进一整套 TLS 栈
- 不引日志框架与时间库。日志格式化加上「东八区时间」的换算，一百来行就够
- 直接依赖只有五个：`windows`、`tray-icon`、`hidapi`，加上 `serde` 这一族的
  `serde` / `serde_json` / `serde_yml`

## 怎么开始用

1. 从 Release 下载 zip，解压到任意目录（比如 `C:\Tools\PowerRing`）
2. 双击 `powerring.exe`
3. Windows 会拦一下（未签名的开源程序都这样），点「更多信息 → 仍要运行」

Windows 10 会把新托盘图标收进 `^` 里，找不到就去任务栏设置里把它打开。
升级时先右键退出，再把新包覆盖到**同一个目录**（启动项的路径记在注册表里）。

## 参与方式

四条路，按需要的技术程度排：

1. **报个数据**：设备没被认出来 → 右键「导出设备信息…」→ 贴到 Issue 或收集页。
   不用懂代码，这段文本里没有序列号、接口路径和蓝牙地址
2. **加一份声明**：`devices/` 下复制最接近的一份改几行。
   完整字段说明与抓包流程见 [adding-a-device.md](adding-a-device.md)
3. **改代码**：先看 [CONTRIBUTING.md](../CONTRIBUTING.md)，代码要求与 PR 格式都在里面
4. **报安全问题**：走 GitHub Security Advisory 私下说，别开公开 Issue

## 状态

从 2026-10 开始做，版本 0.2.x。目前是**单人维护 + AI 协作**的小项目，
没有承诺、没有路线图，改动的驱动力是「自己用着不顺手」和「有人报上来的设备」。

已上真机验证的设备写在 README 的表里，每份声明都标了 `protocol_source`
（协议常量出处）与 `verification`（是否上过机）。**没上过机的一律标 `unverified`，
不会被当作可信数据。**

许可证 MIT。协议常量属事实信息可以移植，但本项目不复制任何 GPL 项目的源码 ——
Solaar、HeadsetControl、OpenRazer 这些项目的存在让这件事成为可能，声明里的
`protocol_source` 就是为了记下这笔账。
